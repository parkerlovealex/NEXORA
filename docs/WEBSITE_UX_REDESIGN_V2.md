# NEXORA Website UX v2 — User-Agent Generator

**Status:** Implemented in the supplied website source package. Static/browser visual QA is partially blocked by the execution environment; production deployment is not verified.  
**Reference:** User-supplied UserAgentGen saved HTML snapshot and `User-Agent.zip` Python source scripts.  
**Catalog:** `web/devices.json`, dataVersion `2026.11.25.6`.

## Design direction

The public site is now a focused User-Agent generator. The public navigation is intentionally limited to the generator; device catalog, app versions and system controls remain administrator-only after sign-in. The public experience uses one graphite/mint visual system rather than a theme selector or extra tools/marketing sections.

The generation flow follows the supplied reference's core sequence:
1. Platform and batch quantity.
2. Device distribution and exact model selection.
3. Browser families and optional in-app applications.
4. Advanced browser versions, locale and output preferences.
5. Generate, inspect, copy or export.

## Implemented generator UX

- Platform switch: Android, iOS, or Both.
- Batch presets: 10, 25, 50, 100, 250 and 500; Android/iOS quantities remain independently editable. Combined maximum is 500.
- Device distribution: Random, Selected, Balanced and Custom per-device quantities.
- Searchable device selection with platform tabs, select-visible and clear-visible actions.
- OS options: latest supported per device, random supported, or a specific supported version. Explicit OS selection filters ineligible devices; custom mode reports unsupported combinations.
- Browser choices with brand marks:
  - Android: Chrome, Firefox, Edge, Opera and Android WebView.
  - iOS: Safari, Chrome, Firefox and Edge.
- Chrome Android and Chromium/WebView engine versions use the catalog value. Browser versions absent from the database remain manual inputs; the reference snapshot's browser versions are not silently treated as verified live values.
- Optional in-app User-Agent generation. It is off by default. The 18 application records show their app version/build and real brand marks. Only records with `status=verified` in `ua_templates.json` can be selected.
- Facebook and Instagram show collapsible candidate-format previews derived from the supplied Python scripts:
  - Facebook Android and iOS.
  - Instagram Android Samsung and Motorola variants, plus iOS.
  These are explicitly labelled candidate formats, not verified output templates. The scripts' randomized suffixes/build identifiers are not promoted to official database facts or generated by the site.
- Advanced locale uses the 148 language/locale options from the supplied reference. Country selection filters devices by the published catalog's market codes. Language is exported as Accept-Language metadata, not inserted into standard browser UA strings.
- Output cards show the actual full UA string, platform/browser or app logo, device/OS and app/browser version details.
- Copy one, copy all, TXT, JSON and CSV export. TXT contains exactly one User-Agent string per line, matching the supplied Python scripts' output-file convention.
- Local saved sets remain in the current browser; they are not uploaded to a customer cloud account.
- Optional sound feedback is off by default. Transitions respect `prefers-reduced-motion`.
- Real Simple Icons brand SVGs load from `cdn.simpleicons.org`; text initials are used if a remote logo is unavailable.

## In-app User-Agent source interpretation

The supplied `User-Agent.zip` entries have `.txt` filenames but contain Python generator source code, not generated UA output files. The UI therefore presents their string layouts as candidate format previews. The Facebook/Instagram code includes app-specific token blocks and platform-specific structures; these are not equivalent to normal Chrome/Safari UAs.

No app template is marked verified. The existing `docs/UA_TEMPLATES_SPEC.md` still governs collection and verification. The site continues to load the separate `ua_templates.json` only when published; no `ua_templates.json` was fabricated as part of this UI work.

## Administration

- Public visitors see only User-Agent Studio.
- Device Catalog, App Versions, System Overview, Compatibility, Sources & Automation, Review Queue, AI Assistant, Audit Log and Settings remain available after administrator sign-in.
- No admin API or secret values are exposed in public frontend code.
- Signing out while on any administrator page returns to the generator.
